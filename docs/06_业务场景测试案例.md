# 06 业务场景测试案例（SmartDock）

> 覆盖 M1 南向采集链路的 7 个业务场景、17 项断言。执行脚本：`scripts/run-scenarios.ps1`（用例数据：`deploy/sql/scenarios/`）。
> 最近执行：2026-11-08（第 2 轮，全面复审修复后），**17/17 通过**；单测 16/16（新增驱动工厂异常隔离回归）。

## 1. 测试范围与链路

```
场景数据（device/device_point 台账） → Platform.Host 启动加载注册表
  → 驱动工厂按 driver_id 实例化 ModbusTcpDriver → 每设备独立轮询循环（5.5）
  → 有界队列攒批（2.6A）→ COPY 落库 point_history → REST 快照 API
```

| 验证维度 | 覆盖场景 |
|---|---|
| 采集正确性 | S1、S2 |
| 多设备与台账管理 | S3、S5 |
| 韧性（5.8 重连 / 3.2 故障隔离） | S4、S6 |
| 停机与数据完整性（2.6A） | S7 |

## 2. 环境与前置

| 项 | 值 |
|---|---|
| 数据库 | PostgreSQL `192.168.106.128:5435`，库 `smartdock`（DDL：`deploy/sql/V001~V002`） |
| 设备模拟 | `tools/ModbusSlaveSimulator`（Modbus TCP :5020，FC03，sine 波 50~150，Float32/CDAB） |
| 平台 | `src/Platform.Host`（:5000，`--no-launch-profile --urls` 显式固定端口） |
| 断言通道 | REST `/api/snapshot`、`/api/snapshot/summary` + SQL 直查 `point_history`/`device` |

执行方式：

```powershell
powershell scripts/run-scenarios.ps1 -Scenario ALL   # 全量（约 4~6 分钟）
powershell scripts/run-scenarios.ps1 -Scenario S4    # 单场景
```

注意：台账在 Host 启动时加载一次，场景间通过**重启 Host** 应用台账变更（M1 静态注册表，热加载属后续能力）。

## 3. 场景案例

### S1 单设备采集全链路

| 项 | 内容 |
|---|---|
| 目的 | 验证「台账 → 驱动 → 流水线 → 落库 → API」全链路正确 |
| 数据准备 | `s1_reset.sql`：清空台账，重建 SIM-001（10 点，`40001~40019:Float32:CDAB`，1s 周期） |
| 步骤 | 复位台账 → 启动 Host → 轮询快照直至全 Good → 间隔 6s 对比落库行数 |

| 断言 | 判据 | 最近结果 |
|---|---|---|
| S1.1 快照全点 Good | `total=10 且 good=10` | PASS（10/10） |
| S1.2 落库持续增长 | 6s 窗口行数递增 | PASS（40120 → 40230） |
| S1.3 最近数据质量 Good | 近 5s 落库行 quality=0 | PASS（30 行） |

## 5. 调试过程中发现并修复的问题（测试的附带价值）

| # | 问题 | 根因 | 修复 |
|---|---|---|---|
| 1 | 种子地址生成出 `400011`（6 位）坏地址，10 点中 5 点 Bad | SQL `format('4000%s:...', 1 + (i-1)*2)` 字符串拼接在偏移 ≥11 时拼错位 | 改为整数加法 `format('%s:...', 40001 + (i-1)*2)`，驱动按 `address - 40001` 解析偏移 |
| 2 | 场景断言按 `device_id=1/2` 硬编码失败 | S1 复位后 bigserial id 不再从 1 开始 | 断言 SQL 改按 `device_code` 关联 |
| 3 | S6.1 断言 `total=32` 失败 | 连不上的设备点位**从未读过**，快照无条目（正确行为） | 断言改为「good=30 且坏设备点位缺席快照」 |
| 4 | S7.1 强杀前后行数差 460 | 测量窗口落在 kill 前，强杀前最后批次已落库（正确行为） | 断言改为 kill 后取基线、4s 窗口 delta=0 |
| 5 | PS1 脚本中文解析错乱（ParserError） | UTF-8 无 BOM 被 PowerShell 5.1 按 GBK 读 | 两个 ps1 补 UTF-8 BOM（新脚本需带 BOM） |
| 6 | DbInit `--sqlfile` 路径被当连接串 | 场景参数消费条件漏了 `sqlFileMode` | 参数消费条件补全 + 场景参数先于连接串解析 |
| 7 | `PointHistoryCopyWriter` 头部中文注释乱码（双重编码损坏） | 文件曾以错误编码保存 | 重写注释，恢复文档-代码可追溯性 |
| 8 | 驱动工厂抛异常（未知 driver_id / endpoint JSON 损坏）会静默杀死设备循环 | `Task.Run` 内未观测异常无人接 | `PollingScheduler` 外层兜底：异常 → 指数退避重建驱动重试 + LogError 告警（3.2 失败策略） |
| 9 | 驱动读取消（停机）被转成 Bad 值写入快照/落库 | `OperationCanceledException` 被当作读失败处理 | 驱动把取消按取消语义上抛，不产生假 Bad 记录（5.7 质量码只描述真实通信结果） |

## 6. 已知边界（本阶段不覆盖）

- **优雅停机排空**（2.6A 停止语义）：S7 用强杀验证冻结；`StopAsync` 排空已由单测 `Pipeline_FlushFailure_DoesNotLoseBatch`/停止排空路径覆盖，E2E 级别的 SIGTERM 优雅停机验证随 Windows 服务安装（12.2）补。
- **写路径（WriteGuard 四道闸）**：M1 后续任务，驱动 `SupportsWrite` 后补场景。
- **MES 北向（Outbox/幂等/对账）**：M2 范围。
- **长时间稳态（7×24）**：M1 里程碑判据，需要真实/长时模拟环境。
