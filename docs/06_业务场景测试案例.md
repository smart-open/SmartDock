## 1. 测试范围与链路

```
场景数据（device/device_point 台账） → Platform.Host 启动加载注册表
  → 驱动工厂按 driver_id 实例化 ModbusTcpDriver → 每设备独立轮询循环（5.5）
  → 有界队列攒批（2.6A）→ COPY 落库 point_history → REST 快照 API
```

| 验证维度 | 覆盖场景 |
|---|---|
| 采集正确性 | S1、S2 |
| 多设备与台账管理 | S3、S5 |
| 韧性（5.8 重连 / 3.2 故障隔离） | S4、S6 |
| 停机与数据完整性（2.6A） | S7 |

## 2. 环境与前置

调试修复记录（3 处，均为单测/联调暴露）：
1. **表名提取误捕关键字**：`@from AND` 中 `@from` 的 `from` 被 TableRefRegex 当成 FROM 关键字后的表名（`\b` 在 `@` 与 `f` 间成立）→ 误报 `not in whitelist: AND`。修：表名提取前先抹掉 `@param` 引用。
2. **params jsonb 数字默认值反序列化失败**：`"default":200` 是数字，`string? Default` 收不下 → 改 `JsonElement? Default` + `DefaultText` 字符串形态。
3. **种子模板列名与真实表不符**：production_report 无 `step_id`（实为 order_id+step_no 复合），work_order 无 `plant_id` → 模板改为复合 JOIN + `/*SCOPE*/ AND o.id > 0`（M3 阶段范围字段未建，占位恒真；RBAC scope 扩展后收窄）。

**范围注入口径**（重要）：编译器契约已冻结——模板必须含 `/*SCOPE*/` 且 `@scopeIds` 由平台注入、用户不可传（伪造被覆盖）。M3 阶段用户数据范围（全部/工厂/车间/本人）尚未建，平台先传全量范围；04 验收 #27「越权查不到数据」的完整闭环依赖后续 RBAC scope 字段，届时只需换平台侧 scopeIds 来源，模板与编译器零改动。

### S11 最小进程外宿主（M1-8，§4.7 L2 / §4.8.1 / 13.1 C1）

前置：`tools/PluginHost`（gRPC 子进程，Kestrel h2c 明文 HTTP/2，动态端口经 stdout `SDGRPCPORT:nnnn` 报告）；`RemoteDriverSupervisor`（主进程侧监管器）。

| 断言 | 判据 | 结果 |
|---|---|---|
| S11.1 拉起 + 全链路读 | Supervisor 拉起子进程（OS 动态端口）→ `RemoteDriverProxy.ReadAsync` 经 gRPC 得 Good 值（PollingScheduler 视角与本地驱动无差别，4.7 隔离透明） | PASS |
| S11.2 心跳判死 | 强杀子进程 → Supervisor 心跳 3 连败（≈6s，含 2s deadline 重试）→ 状态离开 Running 进入 Restarting | PASS |
| S11.3 崩溃自动重启恢复 | 退避 1s → 重新 spawn → 3s grace → 新 gRPC 通道 → 40s 内读恢复 Good（真实子进程 E2E，xunit `RemoteSupervisorE2eTests`） | PASS（连续 2 轮稳定） |

调试修复记录（骨架期踩坑，均有 E2E 断言兜住）：
1. **h2c 双端明文 HTTP/2**：client 侧 SocketsHttpHandler 默认对 `http://` 发 HTTP/1.1 → gRPC 握手被关；server 侧 Kestrel 明文端点默认只开 HTTP/1.1 → `HTTP_1_1_REQUIRED (0xd)`。修：client 用 DelegatingHandler 强制 `Version20 + RequestVersionExact`；server `ConfigureKestrel(HttpProtocols.Http2)`。
2. **`BeginOutputReadLine` 必须在 `Process.Start()` 之后**（未启动无 stdout 流）。
3. **stderr 必须异步排空**：重定向但无人读，缓冲满会阻塞子进程。
4. **restart 链路禁用已取消的 monitor token**：backoff/grace 的 `Task.Delay` 若带 monitor token（KillProcessAsync 已取消）会立即 OCE，restart 死在半路——端口等待改独立 CTS，backoff/grace 无参 delay。
5. **restart 后必须重启监视循环**（KillProcessAsync 取消了旧循环）+ 3s grace 防止把刚起来的新进程误杀成振荡。

调试修复记录（压测暴露的真 bug）：
1. **PollingScheduler._activeDrivers 并发写普通 Dictionary**：20 台设备循环并发注册驱动实例 → 内部桶数组损坏（`IndexOutOfRangeException` @ Dictionary.TryInsert），12 台循环崩溃退避；≤10 台属侥幸未触发。修：`ConcurrentDictionary` + `TryRemove`。
2. 验收脚本 PG `format('%02d')` 不支持数字宽度 → `format('%s', lpad(...))`。
3. 抖动 SQL：`ts - LAG(ts)` 是 interval 不能 COALESCE 整数 → `EXTRACT(EPOCH FROM ...) * 1000`。
4. 新 PS1 脚本无 UTF-8 BOM 被 PowerShell 5.1 按 GBK 解析 → ParserError（docs/06 坑 #5 复发，脚本头须加 BOM）。
5. 落库延迟代理指标初版用 `ts > now()-10min` 窗口最大 age——窗口含台账重建前旧行，重启后误报 50s；改「最新 100 行 age max」（实测 0.7s）。
6. S4.2 断言 `good -eq 10` 脆弱：双设备重连时序不定（10+20 点），首次检查可能已全部恢复 good=30 → 改 `good -ge 10`（回归 17/17）。
